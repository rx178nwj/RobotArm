マルチI2Cブリッジ アーキテクチャ概要

アドレス固定（0x36）の AS5600 磁気角度センサ×3ch を、TCA9548A と RP2040 ブリッジを介して単一I2Cで集約。上位からは「1個のI2Cセンサ（0x42）」に見え、3ch分の角度を1kHzで一括取得できる。

データフロー & 整合性

Write / publish

下流 → shadow → publish

Core1 が非activeバッファに全ch書込後、メモリバリアを挟んで active index を原子的にswap。部分更新は決してpublishしない。

Read / snapshot

読出開始時にラッチ

上位の読出トランザクション開始で active を tx_staging へ memcpy。バースト途中のswapに影響されず、6バイトが一貫スナップショットになる。

No clock stretch

非同期キャッシュ応答

読出はpublish済み最新値を即返す。データ経路でクロックストレッチせず、マスタ非依存で堅牢。tearも発生しない。

タイミング収支（1kHz = 1ms 予算）

上流バス占有 — 1ms 周期あたり
上流 3ch一括リード ≈ 210µs (21%) 空き 79% — 余裕
下流 3ch巡回（別コア・別バスで並行）≈ 550µs / 巡回（~1.8kHz）

上流・下流は別バス・別コアで並行動作するため加算されない。律速は下流巡回（≈550µs）で、上位の各1kHz読み出しは常にデータ齢0.55ms以内の値を得る。将来さらに鮮度が必要なら下流を1MHz(FM+)へ移行可能。

ブリッジMCU選定

採用 · 本命
RP2040
  • I2Cスレーブが堅牢・実績豊富（本システムの核）
  • デュアルコアで上流応答と下流ポーリングを物理分離
  • PIOで将来拡張可（真の同時サンプリングも代替可能）
  • 無線なしで決定性が高い／最安クラス
次点 · 条件付き
ESP32-C3
  • I2Cスレーブに歴史的な制約／クセ
  • 無線スタックがリアルタイム性のリスク
  • Wi-Fi/BLE内蔵・Flash内蔵は利点
  • 無線送信/OTAが要件化した場合に再検討

確定した設計判断

  • ✓通信モデル：レジスタマップ型 — ポインタ＋auto-increment。上位は標準I2Cドライバを流用可。
  • ✓速度：上下流とも 400kHz — 1kHz/3ch要件を満たす。1MHz(FM+)へ移行可能な設計。
  • ✓同時性：各軸を個別に1kHz監視 — TCA9548A方式を維持（ch間スキュー≈340µsは許容、PIO並列は不採用）。
  • ✓整合性：ダブルバッファ＋スナップショット — ロックフリーで一貫読み出しを保証。
  • ✓実装：ベアメタル（RTOSなし）・pico-sdk / C — 2コア=2役割。WDT相互監視で自己回復。
  • ✓電源：全系3.3V — レベル変換不要（将来5V化用フットプリントは予約推奨）。
  • ✓AS5600設定：RAW_ANGLE ＋ CONF=0x0A00 — SF=4x(応答0.55ms)＋高速フィルタ7LSB。起動時に揮発書込、E2E遅延≈1.6ms。
  • ✓回転方向：DIRをブリッジがch毎に駆動 — GP5/6/7で各AS5600のDIRを独立制御（各プルダウン10kΩ）。レジスタ0x32 DIR_CONFIGで設定、既定は全ch CW増加。
  • ✓接続ch数：1ch/2ch/3ch対応 — 起動時自動検出（CH_PRESENT 0x18）＋上位上書き（CH_ENABLE 0x36）。有効chのみ巡回、無効ch(未使用)は角度0xFFFF・DEGRADED対象外。配線どおりなら無設定で正常起動。
