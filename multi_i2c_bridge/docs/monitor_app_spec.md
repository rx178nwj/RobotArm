[usb_serial_spec.md](usb_serial_spec.md) で定義したUSB-CDCテキストプロトコルを用いて、複数の `multi_i2c_bridge` デバイスをWindows/Ubuntu上から同時に監視するデスクトップアプリの仕様。

## 1. 目的・位置づけ

`multi_i2c_bridge` は開発・製造検査・実機デバッグの現場で**複数台同時に**USB接続される（ロボットアーム各関節など）。[usb_serial_spec.md](usb_serial_spec.md) のテキストコマンドはターミナルソフトからも操作できるが、複数台を同時に見比べる・角度変化を波形で追う用途には向かない。本アプリはこれを補い、以下を目的とする：

1. **複数デバイス同時監視**：PCに接続された複数の `multi_i2c_bridge`（各6ch、AS5600×最大6）を自動検出し、デバイスごとに独立したモニタ画面で表示する。
2. **角度の可視化**：現在角度を直感的に把握できるゲージ表示と、時間変化を追える波形表示の両方を提供する。
3. **接続状態の可視化**：「PC⇔ブリッジ間のUSBシリアル接続」「ブリッジ⇔上位コントローラ間のI2C（マスタ側、ブリッジがスレーブ）」「ブリッジ⇔AS5600間のI2C（ブリッジがマスタ、各chがスレーブ）」の3階層の通信状態をそれぞれ独立に表示する（§5.2）。

**非目的**：[usb_serial_spec.md](usb_serial_spec.md) §6 の AS5600 raw read/write（強制制御）・§5 の保守コマンドはv0.1のスコープ外とする（§7「将来拡張」参照）。本アプリは監視系（§4.2-4.6）専用として最小スコープで設計する。

---

## 2. 対象デバイスとデータソース

- 対象センサはAS5600（磁気式ロータリエンコーダ）固定。角度データは `channels` コマンド出力の `ANGLE`/`DEGREE` 列（[usb_serial_spec.md](usb_serial_spec.md) §4.3）を用いる。
- 1ブリッジ = 6ch（ch0-5）。将来的なch数変更は `status` コマンドの `present`/`enable` ビット幅から動的に読み取り、6ch固定にしない（[usb_serial_spec.md](usb_serial_spec.md) §8の6ch化と同様の拡張が今後も起こり得るため）。
- データ取得は各デバイスに対して独立した `monitor <period_ms>` コマンド（[usb_serial_spec.md](usb_serial_spec.md) §4.7）を発行し、非同期出力される `STATUS`/`CH ...` ブロックをパースするストリーミング方式を基本とする（§4.1）。

## 3. 実装アーキテクチャ（前提）

| 項目 | 選定 |
|------|------|
| フレームワーク | Electron |
| 言語 | TypeScript |
| シリアル通信 | Node `serialport` パッケージ（メインプロセス側） |
| チャート描画 | レンダラープロセス側、Canvas/WebGLベースのリアルタイムチャートライブラリ（波形の高頻度更新に対応できるもの） |
| プロセス構成 | メインプロセスがデバイス列挙・シリアルI/O・パースを担当し、パース済みデータのみIPCでレンダラーへ送る（シリアル生データをレンダラーに流さない） |

- Windows/Ubuntu共に `serialport` のネイティブモジュールがビルド対象。配布はプラットフォーム別パッケージ（`electron-builder` 等）とする。
- Ubuntuでは `/dev/ttyACM*` へのアクセス権限（`dialout` グループ）が前提。権限不足時はアプリ起動時にエラーダイアログで案内する（§6.4）。
- USB切断・多重接続時の `/dev/ttyACM*` 番号再割当て（Ubuntu）・COMポート番号変化（Windows）に対応するため、デバイス識別は後述§4.2のシリアル番号ベースとする（ポート名を固定キーにしない）。

## 4. デバイス管理

### 4.1 デバイス検出・登録

- アプリ起動時にシステム上のシリアルポート一覧を列挙し、USB VID/PIDが `multi_i2c_bridge`（RP2040 USB-CDC）に一致するものを候補として自動リストアップする。
- 候補ポートに対して `help`（または `status`）コマンドを送信し、応答があるものを有効なブリッジとして認識する（無関係なUSB-CDCデバイスの誤認識を防ぐ）。
- ユーザーは検出済みポートを個別に「接続」操作して監視を開始する（自動全接続はしない。他プロセスが同一ポートを使用中の可能性があるため）。
- 手動でポートを指定して接続する導線も用意する（自動検出に失敗するデバイス・カスタムファームウェア向け）。

### 4.2 デバイス識別

- 各ブリッジをアプリ内で一意に識別するキーとして、OSが報告するUSBデバイスのシリアル番号（RP2040のユニークID相当）を使用する。ポート名（`COM3`/`/dev/ttyACM0` 等）は再接続で変わり得るため識別キーにしない。
- ユーザーはデバイスごとに表示名（ラベル、例：「J1 shoulder」「J4 wrist」）を設定でき、シリアル番号に紐づけて設定ファイルに保存する（§6.3）。
- 未接続時・初回接続時はシリアル番号を短縮表示したデフォルト名を用いる。

### 4.3 同時接続数

- 上限は設けない（実運用ではロボットアームの関節数程度、数台〜十数台を想定）。ただし後述のUIはデバイス数に応じてスクロール/タブで破綻なく表示できる設計とする（§5.1）。

## 5. UI仕様

### 5.1 全体レイアウト

- **左サイドバー（デバイス一覧）**：接続中/検出済みの全デバイスを縦リスト表示。各行に以下を常時表示：
  - デバイスラベル（§4.2）
  - シリアル接続状態アイコン（§5.2.1）
  - 上流I2C（マスタ）通信状態アイコン（§5.2.2）
  - 下流I2C（AS5600群）の総合状態アイコン（chのいずれかがFAULT/未接続なら警告表示、§5.2.3）
  - リスト項目をクリックすると右側のメイン表示エリアに当該デバイスの詳細を表示する。
- **メイン表示エリア**：選択中デバイスの詳細（§5.3）。複数デバイスを同時に並べて見比べたい場合のため、グリッド表示モード（複数デバイスのミニパネルを並列表示）も提供する。
- **グローバル操作**：全デバイス一括「monitor開始/停止」、更新周期設定（既定1000ms、[usb_serial_spec.md](usb_serial_spec.md) §4.7の受理範囲100-60000msに準拠）。

### 5.2 接続状態表示（3階層）

USBシリアル・上流I2C・下流I2Cは独立した通信区間であり、いずれか1つが不通でも他は生きている場合があるため、必ず**個別に**表示する。

#### 5.2.1 モニタ状態・シリアル通信状態（PC⇔ブリッジ）

| 状態 | 判定条件 | 表示 |
|------|----------|------|
| 未接続 | ポート未オープン | グレー |
| 接続中・応答待ち | ポートオープン済み、`monitor`未応答 | 黄（点滅） |
| 監視中 | `monitor`コマンドで周期出力を受信し続けている | 緑 |
| 通信断 | オープン済みだが規定タイムアウト（更新周期の3倍を目安）内に応答なし | 赤 |
| エラー | シリアルポートI/Oエラー（デバイス切断等） | 赤（エラー内容をツールチップ表示） |

- 「モニタ状態」（`monitor`コマンドが動作中か）と「シリアル通信状態」（ポート自体が生きているか）は概念上別軸だが、v0.1ではシリアル監視が本アプリの主用途のため統合したインジケータ1つで表現し、詳細はツールチップ/デバイス詳細画面で内訳を出す。

#### 5.2.2 上流I2C通信状態（ブリッジ⇔上位コントローラ、ブリッジ=スレーブ）

- `master`コマンド（[usb_serial_spec.md](usb_serial_spec.md) §4.5）の `last_activity_ms` を定期取得し、直近取得値の更新が続いているかで生死判定する。
- 表示ラベル例：`MASTER: active`（緑、last_activity_msが直近更新周期内で進んでいる）/ `MASTER: idle`（黄、応答はあるが一定時間活動なし＝上位コントローラ未接続や停止中の可能性）/ `MASTER: unknown`（灰、ブリッジ自体から応答が得られない）。
- `write_tx`/`read_req` 等の累積カウンタも詳細画面に表示する（通信量の把握用）。

#### 5.2.3 下流I2C通信状態（ブリッジ⇔AS5600、ブリッジ=マスタ）

- ch単位で `channels` 出力の `PRESENT`/`ENABLE`/`OK` を参照し、以下のいずれかのステータスに分類して表示する：

| ステータス | 条件 | 表示色 |
|-----------|------|--------|
| 未実装 | `PRESENT=0` | グレー |
| 無効化 | `PRESENT=1, ENABLE=0` | 灰青（意図的な無効化） |
| 正常 | `PRESENT=1, ENABLE=1, OK=1` | 緑 |
| 故障 | `PRESENT=1, ENABLE=1, OK=0` | 赤 |

- デバイス一覧の総合アイコン（§5.1）は、いずれかのchが「故障」なら赤、「故障」はないが「未実装」以外に「無効化」が混在する等は黄、全ch正常なら緑とする。
- ch別の詳細（`READ_OK`/`READ_ERR`/`LAST_OK_MS`/`LAST_ERR_MS`、[usb_serial_spec.md](usb_serial_spec.md) §4.3）はデバイス詳細画面のch一覧テーブルに表示する。

### 5.3 デバイス詳細画面

1台のブリッジについて、以下を1画面にまとめる：

1. **ヘッダ**：デバイスラベル、シリアル番号、ポート、§5.2の3階層状態インジケータ、`status`のFAULT/CH_FAULTデコード結果（[usb_serial_spec.md](usb_serial_spec.md) §4.2）。
2. **角度ゲージ表示**：ch0-5（有効chのみ、または全ch常時）を円形ゲージ（0-360°、針または円弧で現在角度を表示）としてグリッド配置。ch番号・現在角度[°]・AGC値を併記。無効/故障chはゲージをグレーアウトし `invalid`/故障表示にする（[usb_serial_spec.md](usb_serial_spec.md) §4.3の `invalid` マーカに対応）。
3. **時系列波形表示**：横軸=時間、縦軸=角度[°]（0-360、または連続性を優先する場合は巻き数考慮の展開角度も選択可能とする、§7候補）。ch別に色分けした折れ線を同一グラフに重畳表示。表示区間は直近N秒（既定60秒、UIで変更可）のスライディングウィンドウ。凡例でch表示/非表示を切替可能。
4. **chステータステーブル**：`channels`出力の全列（[usb_serial_spec.md](usb_serial_spec.md) §4.3表）をそのまま一覧表示。§5.2.3の色分けをテーブル行に適用。
5. **上流I2C（マスタ）パネル**：§5.2.2の状態・カウンタ・`last_activity_ms`の推移。

### 5.4 配色・アクセシビリティ

- 状態色（緑=正常/黄=注意/赤=異常/灰=非活性）はch識別色（波形の線色）とは独立したパレットを用い、混同を避ける。
- 色のみに依存しないよう、状態インジケータには常にテキストラベル（`OK`/`FAULT`/`DISABLED`等）を併記する。

## 6. 動作仕様

### 6.1 ポーリング/ストリーミング方式

- 基本方式：デバイスごとに `monitor <period_ms>` を発行し、継続出力される `STATUS`/`CH ...` ブロックをパースしてUIへ反映する。
- `monitor` 停止時（ユーザー操作またはデバイス側デフォルト状態）は、明示的に `status`/`channels` を単発発行してスナップショット表示に切り替える。
- [usb_serial_spec.md](usb_serial_spec.md) §3の「応答は同期的（1コマンド送信→対応する応答を受信してから次を送る運用を推奨）」との整合のため、`monitor`実行中は他の単発コマンド（`master`等）を割り込ませる際、送信間隔を空けてキューイングする（同時送信で応答が混線しないようにする）。

### 6.2 タイムアウト・再接続

- 規定時間（更新周期の3倍を目安、§5.2.1）応答が得られない場合は通信断と判定し、UIに反映する。
- USBの物理切断（OSレベルのポート消失）を検出したら即座に「未接続」に遷移し、自動再接続は行わない（同一デバイスの再接続時にユーザーが明示的に「接続」操作することで、意図しない多重オープンを防ぐ）。ただし同一シリアル番号のデバイスが再度検出された場合、サイドバー上の該当エントリを更新し「再接続可能」であることを表示する。

### 6.3 設定の永続化

- デバイスラベル（§4.2）、更新周期、波形表示区間長、レイアウト（単一/グリッド表示モード）をローカル設定ファイルに保存し、次回起動時に復元する。

### 6.4 エラーハンドリング

- シリアルポートオープン失敗（権限不足・他プロセスが使用中等）は、OS別に想定される原因をエラーメッセージに含める（例：Ubuntuで `dialout` グループ未所属の場合の対処法を案内）。
- パース不能な応答行（想定外フォーマット）は当該行を無視し、詳細画面のログ欄（§7候補）にraw表示できるようにする（デバッグ用）。

## 7. 将来拡張候補（v0.1スコープ外）

- [usb_serial_spec.md](usb_serial_spec.md) §5の保守コマンド（`rescan`/`fault clear`/`mux reset`/`ch enable|disable`/`ch dir`/`reboot`）をUIから発行する操作パネル。
- §6のAS5600 raw read/write（強制制御）のGUI化（安全確認ダイアログ必須、特にBURN禁止・CONF不整合警告の可視化）。
- `log`コマンド（[usb_serial_spec.md](usb_serial_spec.md) §4.6）による上流I2Cトランザクションログのビューア。
- 波形データのCSV/ログファイルへのエクスポート。
- 角度の巻き数（多回転）を考慮した連続角度表示・速度（角速度）算出。
